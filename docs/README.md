# Documentation

Start here. The guides are written for a junior engineer joining the project; read them in the
order below the first time, then use them as reference.

| Guide | Read it when |
|---|---|
| [How the app works](how-the-app-works.md) | First day. A walk from the UI to the code for one complete run. |
| [Architecture](architecture.md) | You need to know where something lives and why it lives there. |
| [Developer guide](developer-guide.md) | Setting up, running tests, adding a step or a data source, opening a PR. |
| [Logging and debugging](logging-and-debugging.md) | Something failed and you have a request id. |
| [API reference](api.md) | Building against the API or changing an endpoint. |
| [Deployment](deployment.md) | Shipping to AWS, rotating secrets, tightening IAM. |
| [NLP and sentiment analysis primer](nlp-sentiment-primer.md) | You are new to NLP and want to understand what the pipeline is for. |
| [Data cleaning guide](data-cleaning-guide.md) | Deciding which preprocessing techniques to use for a given dataset. |
| [Design system](design-system.md) | Tokens, the glass surface, selected/focus states, how contrast is verified. |
| [Decisions](decisions.md) | Why the stack looks the way it does; what was deliberately left out. |

Screenshots live in `images/`. The Swagger UI at `/docs` is always the authoritative API contract.
